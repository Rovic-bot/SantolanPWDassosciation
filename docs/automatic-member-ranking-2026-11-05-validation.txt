Implemented behavior

the current recorded household monthly income and explicit household 4Ps Yes/No;
HM uses the current recorded household count. ES uses an explicitly saved mapping
from registration employment status to the existing engine categories. No default
production mapping is invented: Programa reuses the existing fixture-only
Employed -> Full-Time Worker / Unemployed -> Unemployed mapping from the local
test rules previously chosen by the owner. Other statuses require an explicit
policy mapping or correction; they do not silently become unemployed.

PA continues to use confirmed, non-voided actual releases under the same saved
scope, date window and recording cutoff. A zero count means zero qualifying
recorded releases. Missing, invalid or unsupported member values remain blockers.
Membership approval, active membership, program eligibility, actual program
requirements and the review of unresolved change reports remain enforced.

The automatic source has explicit current-record periods. It does not copy one
monthly value into three invented historical observations. The old monthly-
averaging and individual evidence-review-age fields are inactive for this source.
Current policy validity, closed intake and cutoff gates remain enforced.

Generation captures member ID/version, the exact selected fields, source digest,
ledger releases, configuration and weights in the immutable calculation snapshot.
Replay derives inputs again from that saved snapshot, never from today's member
record. No DatasetInputReview rows or manual verification findings are fabricated.
GET readiness remains read-only. Changes require a new complete-pool calculation;
old runs stay reproducible. Confirmed post-cutoff delivery can be projected under
the existing fulfillment contract without changing the earlier scoring inputs.

Ranking displays Member record inputs and Ready for ranking from member records.
The separate input-review link is absent, and old entry URLs redirect to ranking
without recording acceptance. The calculation guide explains current income;
4Ps display labels distinguish recorded values from a separate verification.
Policy draft/review pages expose the exact employment mapping.
