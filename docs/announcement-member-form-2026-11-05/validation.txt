Announcements, full member record, and program application cleanup
5 November 2026

Owner-requested changes

Announcement creation now uses an accessible plus link on the right of the
filter box, on both the program-results chooser and notices list. The prior
standalone Create announcement link was removed. The plus keeps its accessible
name, keyboard behavior, existing creation route and add-announcement permission.
Automatic filters remain GET forms; the creation link is outside those forms.

The full member record no longer links to a separate Original membership
application page. Its inline section is titled Registration information. This
preserves the earlier explicit request to show the complete registration data
inside the member record. The source intake, protected history, approval routes,
registration printing and access controls were not deleted.

Confirmed program applications no longer collect a contact number, including
through a hidden field. The audited submission service rebuilds the form with
the locked verified member and saves the directory contact in its private
confirmation snapshot, marked contact_source=member_record. Public overrides
are ignored. Later member edits do not rewrite earlier application snapshots.
The copied number is not exposed on the public form or presented as an
applicant-supplied declaration in the new application review. Older submitted
contact declarations retain their original display and data.

Removed the requested screening, explanatory, Help Desk, document-reuse,
upload-guidance and upload-limit paragraphs. Application details, program-specific
instructions, configured requirements and the remaining inputs are retained.
Actual file validation, limits, CSRF, verification/disability gates, current
information reporting and file retention on validation errors still apply.
