EWAF ranking, applicant review and score breakdown UI - 2026-10-27

Owner-authorized scope
Implemented the three supplied reference screenshots in the existing Django
Admin application. This is a presentation change using saved system data.
The accepted 70% development milestone remains unchanged.

Resulting workflow
The ranking page has Configuration and Generate EWAF Ranking actions, a
three-part summary, Ranking/Score breakdown navigation, applicant search,
a decision filter, exact-rank tie labels, score bars and Review actions.
Search and filtering retain the complete saved normalization pool, scores
and ranks. They never generate a calculation or alter applicant decisions.

Review opens a right-side dialog with the full application reference, rank,
score and saved accepted income, reviewed household 4Ps finding, employment,
qualifying previous assistance and household size. Select for assistance
posts to the existing protected decision service. Completed recipients,
stale calculations, restricted users and held ties retain their controls.
The full applicant profile remains available through its existing private
route. Selection does not itself create an assistance delivery record.

The breakdown page has an applicant picker, score/rank summary, actual
criterion contribution bars, input/weight/points details, optional formulas
and an applicant comparison table. Historical criteria and missing criteria
remain accurately distinguished. Display rounding never determines rank.

Both pages use the existing eight permission-filtered navigation groups.
Only these two screens use compact navigation defaults and a separate
navigation preference key. Other modules and public templates are unchanged.
The review dialog supports Tab/Shift+Tab containment, Escape, close/backdrop
actions, focus return and independent content scrolling. GET links and
ordinary forms remain usable without JavaScript. Mobile tables scroll inside
their cards; the page itself does not overflow horizontally.
Relative text sizes and scoped contrast colors preserve the existing Display
preferences; the actual larger-text and high-contrast controls passed checks.

Failures encountered and resolved
1. The initial 13-case run had one browser failure: native dialog tabbing
   allowed focus to leave the content. Explicit keyboard wrapping fixed it.
   The other 12 tests passed.
2. The first retained-development browser pass found mobile overflow from
   an absolutely positioned hidden table heading. A positioned scrolling
   container fixed the overflow; numeric table cells also avoid line breaks.
3. The single-case browser retry reached applicant switching but asserted
   before its GET navigation completed. The harness now waits for the
   selected applicant in the URL. The full browser journey subsequently passed.
4. The 27-entry regression invocation passed 25 tests in 404.972 seconds.
   One legacy presentation assertion expected the retained human-selection
   accessible label; that label was restored, and the case passed separately
   in 4.064 seconds. One entry used an incorrect test class name and did not
   execute. The corrected RerankingAfterDeliveryTests case passed in
   135.575 seconds. The additional selection/publication case passed in
   87.213 seconds. There are no unresolved failures from these scoped checks.
