Correction
Operational selection and result publication now use current_result_run. With
no program receipts, it retains the existing complete-pool current-run check.
With receipts, it validates the immutable run and exact applicant pool and
reuses delivery_selection's whole-pool checks. Only confirmed deliveries linked
to that run and selection may explain the completed status and additional PA
ledger entry. Every other source, configuration, weight, expiry, evidence or
receipt-binding change still blocks use. Scores, accepted evidence and ledger
records are never rewritten. New calculations still use actual ledger data.
Remaining current decisions can be finalized after a member receives support.
Published selection snapshots remain unchanged by valid fulfillment, while
voiding or corrupting its receipt still withholds publication.

Interface
- Programs use the Program Management card grid on the results workspace.
- Review and publish opens that program's lists below the grid.
- Applicants appear on the left and selected applicants on the right; mobile
  stacks the columns. Both show masked names and full application references.
- Publish results is the explicit publication button.
- When review is needed, the private lists remain visible and publication is
  disabled. Internal application UUID/error codes are replaced with readable
  guidance. These fallback lists never become an official publication source.
- Existing explicit publication permissions, CSRF, stale-page tokens,
  finalization notice, transaction rollback and immutable revisions remain.
