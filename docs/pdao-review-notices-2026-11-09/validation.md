# PDAO review notices and public portal consistency — November 9, 2026

Implemented the owner's current request after reviewing the repository guidance, October 10 target/current boundary, confirmed membership/PDAO amendment, Open Decisions, implementation-impact notes and current PDAO/onsite/email/UI validations. This is scoped authorization for the existing PDAO intake workflow; it does not change Association membership approval, government ID issuance, program eligibility or EWAF.

## Result

- The private PDAO submission receipt now uses the shared public navigation, typography, warm neutral palette, rounded cards and Display controls. It shows the saved reference/contact, next steps and a collapsible form preview. The separately rendered source form retains its two-page A4 print layout; Print/Save prints the iframe, and the ordinary link remains usable without JavaScript. Both receipt and printable copy require the original unexpired session capability, use no-store/same-origin framing protections, and are revoked by Finish. The receipt continues to display the original submission, not subsequent staff corrections.
- Online reviews display the saved PWD number and **Check PWD number in PRPWD**, which opens the configured registry and attempts to copy the number. Ready/Needs information actions for a provided number become available after opening the registry. The server requires that the reviewed number matches the current saved number and that the official configured URL is valid. **Mark ready to forward** records the staff member's manual verified result, version, number and URL, and queues an office-verification invitation. Opening the registry alone never records verification, and there is no government API integration.
- **Needs information** requires a reason, records a distinct status, and emails that reason with instructions to complete the PDAO form again or visit the office because details or the provided PWD number may need correction. An existing number remains optional for new applicants. New online applications require an email for these notices; existing submissions with a missing/invalid address must have it corrected before a notice-producing action. The versioned public privacy notice explains this use of email.
- Staff-created onsite applications retain optional email and the direct Ready → Record forwarded flow. They show neither the online information-request action nor a registry-opening gate, and create no review emails. Recording actual forwarding still requires confirmation of onsite verification and delivery of the signed form/requirements. Forwarded records remain locked.
- Original submissions, channels, references and protected events remain unchanged. Corrections retain append-only revisions, reset readiness, and require a fresh check against the saved number. Needs-information applications cannot skip directly to forwarded. Existing PDAO view/correction/forward permissions and version checks remain enforced; no grants were broadened.
- Separate immutable PDAO notice/attempt records reuse the existing Association sender. Sends happen only after commit. Source locking, version/outcome checks, unique jobs and claim state prevent duplicate clicks/callbacks from resending. Superseded queued notices are cancelled. Known failures can retry the same saved recipient/message; uncertain or accepted sends cannot automatically retry. Review email content/status is available only in the protected review. PWD numbers and medical details are not automatically included in messages.
- Public dark-mode controls now keep matching text/icon colors on hover and keyboard focus, including navigation, pagination, carousel arrows, support links and program actions. The Home event placeholder and photo backing now share the dark surface, removing the light vertical gradient seam. Public print controls also use the neutral palette; the official printed document remains unchanged. Built-in new receipt/guidance text has local Tagalog translations; custom content remains as entered.
