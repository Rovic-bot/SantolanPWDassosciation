# Announcement composer and complete filtered cards — November 10, 2026

Implemented the owner's latest announcement-layout request. It supersedes popup-only presentation for the **Announcements** and **Program Results** public filters; **All** retains the existing compact cards and detail popups.

## Current behavior

- The admin create action opens a native, keyboard-accessible dialog styled with the event builder's numbered sections and the shared public/admin palette. Its only visible creation fields are Title, Content and optional Image. There is an image preview and removal control. Direct create/general-edit URLs open the same editor, with an ordinary form fallback without JavaScript.
- The simplified editor supplies the Association as the responsible source for new notices. Image text identifies the accompanying announcement; the form explicitly asks staff to include all important image information in Content. Existing source offices and reviewed image descriptions remain when editing without replacing the image. Existing linked-program notices retain their original editing path; generated results retain their separate authorization workflow.
- Save creates a private draft and opens the existing review screen. Published notices edited through this composer return to draft. Permission checks, explicit publication, CSRF, image sanitization/private storage, optimistic version checks and protected audit rollback remain in the service. Extra posted category/source/status values do not change the simplified editor's general-notice contract.
- Each filtered public page contains exactly one complete record. Full announcement text is escaped and retains paragraphs; the image is shown without cropping, with title initials when absent or unavailable. Results show the existing authorized public projection, including program information and the published applicant/selection tables. No private admin projection or legacy applicant content is exposed.
- Swipe, arrows and keyboard navigation follow server pagination between individual records. Search/topic changes and browser history work with the existing progressive browsing code. Shorter records use their natural height. Table keyboard/horizontal-scroll gestures remain inside the table. Ordinary pagination remains without JavaScript. **All** retains up to four compact cards across one row and its popups.
- The editor and cards use existing light/dark/high-contrast tokens. Browser checking also found and corrected an unreadable public high-contrast skip link. Admin partial-page navigation disposes and reinitializes the composer through the existing `WorkspacePage` lifecycle.
