Implementation

All four composite criteria retain their exact approved weights. Varying
criteria use the saved program applicant minimum and maximum and existing
directions. When minimum equals maximum, normalized credit is 1. For SES,
income need I = 1 still receives the existing 0.90 / 1.00 household 4Ps
multiplier. Nothing is redistributed. A varying criterion may still have a
legitimate zero at its minimum-scoring endpoint; its contribution is recorded.

The optional versioned calculation_application policy marker activates only
the shared equal-value rule for new compatible composite calculations. Each
new run captures the exact approved policy ID, digest, rule, approval instant
and effective period. Generation tokens include that snapshot; changing the
rule invalidates pending generation requests and requires a new ranking before
further decisions/publication. Replay uses the saved rule, never today's rule.
The run validity cannot extend beyond that rule's approved period.

This does not rebind existing programs, invalidate their accepted input reviews,
substitute member facts, change directions/weights, or rewrite earlier runs.
Existing automatic member-record inputs, Student -> Unemployed score 4,
open-registration ranking, human selection, and retained source checks remain.

The ranking table now displays every saved criterion contribution in points,
including zero, beside the total. Headers follow saved trace codes, preserving
older method signatures. The breakdown and calculation guide explain the exact
equal-value treatment and link its retained policy. Current rule guidance is
separate from the original bound input policy.

Applicant qualification, identity evidence, changed eligibility records and
missing checklist/evidence messages no longer fall through to a misleading
"Scoring settings are incomplete" message. Genuine review requirements remain.
An empty eligible pool receives a specific no-ready-applicants explanation.
