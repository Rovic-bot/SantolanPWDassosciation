# Community Assistance Desk ticket conversation layout

The owner requested the supplied two-column conversation layout when choosing View ticket from the Community Assistance Desk inbox.

The existing protected ticket dialog now has one header containing the subject, status, original reference, received date/time, and close-view control. The left column contains the member's concern, expandable contact information, previously recorded member-facing replies, the reply editor, and expandable system email history. The right column contains private evidence previews/downloads, activity history, and the existing Close ticket action.

The owner's follow-up removes Internal note entirely from the reply editor and its Django form. Replies now require only the member-facing message plus the existing channel/status and concurrency fields. The service records an automatic activity description (email reply or onsite instructions recorded), preserving the audit trail without requesting a manual note. Historical notes remain unchanged. Email/onsite channel choices, status choices, sender/version checks, permissions, automatic review on opening, closed-ticket restrictions, retries, and sending behavior are unchanged.

The desktop dialog is bounded to 1320 pixels and the available viewport height, with scrolling conversation/evidence areas. On smaller screens the columns stack and the header stays accessible while scrolling. Colors use the existing cream/charcoal and semantic accent tokens in light, dark, and high-contrast modes. The standalone ticket URL uses the same layout and native forms remain available without JavaScript.

The later owner-requested [reply channels and closure update](community-assistance-reply-channels-and-closure-2026-11-10.md) supersedes the channel/status controls above: replies now offer Email or Online conversation, the status selector is removed, and Supporting evidence is collapsible.
