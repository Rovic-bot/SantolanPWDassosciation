# Phase 4 design and dependency review

Resources & Help appends the eighth public destination and reuses the existing core PublicContent/ContentRevision draft, authorization, version and history lifecycle. Seven content keys correspond to integrated §5.10. Additive source/provider/review-date/archive fields are metadata, not policy. Resource publication requires an actual source review confirmation; unreviewed pages have no published article. Canonical membership/PDAO guides, programs, Results, Home guidance and Help Desk remain linked rather than copied. No legal claims, provider contacts, calendar dates or jobs are seeded/published by this development.

New migration scope: expand PublicContent key choices without changing field storage, add optional source URL/provider/review-date and an archive flag; preserve existing records with empty/false defaults. No historical migration edits, data migration or EWAF change. It will require exact dependency/hash review and disposable reverse/forward tests. The startup guard remains unchanged and will reject its pending state until a separately authorized migration.

Referral tickets remain blocked: integrated §§5.6/7.11 require a ticket-specific member-verification contract, minimal data, reference allocation, lifecycle, custody and staff authority. The source explicitly leaves ticket statuses undefined; IQ-16 also leaves operational ownership pending. No fabricated Program/assistance case is used. A disabled placeholder is not reported as delivery. IQ-13 authorizes the eighth public destination; it does not approve referral processing.

RSVP remains blocked by IQ-11 audience, fields, duplicate/cancellation/capacity and restricted-attendance prerequisites. Existing program-linked event terms are protected by `programs/terms.py` and EWAF source contracts. New Target Audience/Who May Participate fields would need a reviewed way to bind changes to those existing approved terms. No unlocked parallel admission rule is introduced. Current scheduled events and separately reviewed annual observances remain intact; new General/Specific labeling is deferred where that binding is unavailable.

Public method wording is corrected to the actual approved architecture: configured criteria/weights/normalization, complete-pool readiness, human decisions/capacity/ties and separate actual releases. It does not publish numerical ranks, private reasons, additional identifiers or a separate score engine. Existing published CMS content is not overwritten automatically; it needs authorized review if it contradicts the new fallback wording.
