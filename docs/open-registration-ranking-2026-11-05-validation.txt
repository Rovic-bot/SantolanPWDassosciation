Owner decisions and scope

The owner requested removal of the Verification column from Program Applications
& Eligibility and explicitly required ranking before registration ends, including
fixing the reported evidence-digest error. The owner then selected "Use these
local test rules" for Student -> the existing Unemployed employment score (4)
and zero contribution from a criterion when all applicants have the same value,
without changing or redistributing approved weights.

These instructions supersede the closing-time calculation gate for the newly
versioned local test policy. They do not establish institutional scoring policy,
change the program dates, approve beneficiaries or alter existing scores.

Implemented behavior

Removed the Verification header and cells from the application table, including
its mobile labels; the empty state now spans five columns. Eligibility review
and the underlying identity requirements remain available in applicant review.

The new current_eligible_v1 policy allows ranking while registration is open.
It uses the currently eligible applicants with valid current member-record
inputs. Pending eligibility applications remain in the saved manifest but do
not enter the open-registration ranking. Missing or invalid inputs for an
eligible applicant still block calculation. After registration closes, unresolved
applications must be reviewed before the final complete-pool calculation.

Each run freezes its observation instant and uses the earlier of that instant
and its approved assessment cutoff for the actual-release history. Future dates
or later-recorded releases cannot be counted as observations already made.
Source tokens compare facts rather than elapsed microseconds between opening
the page and clicking Generate. Repeated requests retain idempotency; new
applicants or changed source facts require recalculation. Old runs replay from
their saved member values, ledger inputs, observation time and weights.

The zero_contribution_v1 constant rule and matching calculation-method choice
are explicitly versioned. Equal-value criteria have normalized value zero and
contribution zero for everyone, with no division by zero or weight redistribution.
A single-person pool therefore has score zero. Normal formulas still apply to
varying criteria. Exact competition ranks and existing tie handling remain.
The Student mapping is explicit policy, not a modification of member profiles.
Breakdowns and the calculation guide explain zero contributions.

Open-registration rankings are provisional for beneficiary selection. Final
selection still requires a new complete ranking after registration closing and
the retained assessment cutoff. No selection, publication or actual release
was performed as part of this work.

Schedule digest defect

An authorized schedule update created configuration 40 with a signed cutoff in
Philippine time. MySQL returned the same instant in UTC, changing its string
representation during digest replay. The retained digest and native audit exactly
match the original Philippine-time representation; no evidence was fabricated.

New bindings normalize the cutoff to UTC before signing. Historical payload
validation can reconstruct only the exact previously signed Philippine-time
representation of that same instant. All other fields, schema and native audit
must still match. Changing the actual instant still fails. No stored digest,
configuration or audit was overwritten or resealed.

a new review. Missing or altered witnesses, an unexplained version change,
