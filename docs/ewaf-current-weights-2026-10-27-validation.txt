OWNER-AUTHORIZED WORKFLOW
Edit main weights -> Calculate AHP weights -> Approve configuration.
EWAF Ranking -> select program -> Generate EWAF Ranking -> click applicant name
or score -> view that applicant's retained scoring explanation.

The owner's follow-up authorizes current approved main weights for new composite
SES/ES/PA/HM calculations across existing and new programs. This supersedes the
earlier requirement that each such program use its initial weights forever.
It does not authorize rewriting historical results, changing accepted evidence,
changing formula coefficients, converting historical methods, or selecting people.

IMPLEMENTATION
New composite calculations resolve the latest approved matching Vault version.
The exact AHP vector, approval reference, digest, provenance and approving actor
are retained in the calculation snapshot when they differ from the original
program binding. Replay validates that exact approval; it never substitutes the
current Vault into a saved run. Original binding weights remain the replay source
when no newer shared weight snapshot is present.

The original scoring-policy binding remains immutable. Its accepted-input rules,
evidence, assessment cutoff and source checks remain in force. Weight-only changes
therefore require neither a fabricated evidence acceptance nor a second program
configuration. Drafts and slider previews have no effect on calculation weights.
Program cards and workspaces show the current approved weights; saved result and
explanation pages show the actual version used by that saved calculation.

Approval accepts the signed server AHP preview for the current proposal, method
and Vault version. It atomically records the draft and approval, with existing
permissions and audits. A separate Save weight draft action remains optional.
Missing, stale, altered and forged preview confirmations fail closed. A staff
member who can approve an existing draft still needs configuration authority to
create a changed proposal; no permissions were broadened.

The existing terms lock serializes approvals and calculations. Generation rejects
stale request context and checks its complete snapshot again before committing.
An older ranking cannot support new decisions after a shared weight change until
a current ranking is generated. Prior decisions, selections, deliveries and public
results are not rewritten or automatically issued.

New composite programs and already-open weights-only intakes can use a centrally
approved compatible assessment policy after the main weights change. They retain
that policy's original approval and cutoff rule, while new calculations use the
current main weights. This exception is limited to centrally approved composite
policies; historical methods and explicit historical binding contracts remain
protected. Missing institutional rules or accepted information still block scoring.

The 90/10 composite SES formula, employment encoding safeguards, PA ledger source,
pool bounds, exact fractions, display rounding and competition ties are unchanged.
No model fields or migrations were added. Admin groups and Public Portal behavior
are preserved. The owner-defined 70% milestone remains unchanged.
