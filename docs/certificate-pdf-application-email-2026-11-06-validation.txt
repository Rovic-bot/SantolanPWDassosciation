This later explicit authorization supersedes the historical optional application email and DOCX attachment behavior documented in the preceding validation notes. Other workflow decisions remain unchanged.

Implemented behavior
- The existing OOXML personalization preserves the owner's source template. One isolated, hidden LibreOffice conversion handles the new certificates in a publication. New outbox documents and their hashes contain the resulting PDFs.
- Gmail and Resend attachments and the permission-checked download use the PDF filename/MIME type. Publication and all new outbox jobs roll back if PDF conversion fails. No partial certificate batch is committed.
- Original issued outbox bytes, recipients, provider identity, idempotency and attempt history remain immutable. Historical DOCX records retain their original attachment format for safe retries. Re-publication does not resend previously accepted messages.
- The current public application form requires a valid email (maximum 254 characters) in both the UI and locked submission service. Email is not prefilled from private member records.
- A valid verified submission fills only an empty member email under the existing transaction/member lock. It increments the member version and appends an email_added_from_application MemberEvent identifying the application reference. The application source snapshot records the resulting member version. Audit/submission failure rolls back the email change.
- Existing nonblank member emails stay byte-for-byte unchanged. The application keeps its own address and uses it for eligibility emails and certificates. Duplicate submissions do not replace the first address or add another member audit entry.
- The original onsite registration and its revision history remain unchanged. Current contact details and the member editor already read Member.email; verified both reflect the added email. Existing stale-editor/version safeguards remain active.
