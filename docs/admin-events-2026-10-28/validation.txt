Admin Events simplification — 28 October 2026

Owner-approved follow-up
Remove the Annual calendar reference section, the Manage scheduled General and
Specific Events link, and the Create observance button. Add Create event. Opening
an existing observance must allow editing and publishing its update in one save.
This replaces the withdraw/edit/republish instructions in the earlier annual
calendar validation note. Earlier unfinished changes remain preserved.

Implemented behavior
- Admin Events shows the twelve-month saved calendar and Create event, linked to
  the existing scheduled-event creation form with its existing permissions.
- Authorized editors open an observance directly from its title. Save and publish
  validates and publishes the complete edit atomically, returning to the calendar.
- Existing change AND publication permissions are required; no permissions were
  granted. Read-only users retain the detail view. Archived cards require the
  existing explicit restore action before editing; ordinary draft/published cards
  can be updated and published directly.
- The edit form clearly explains immediate publication. Audience and participation
  fields are required in this publishing flow. The reason remains recorded.
- Current-version checks, row locking, photo validation, complete immutable
  revision snapshots and audit records remain. Stale edits, invalid content,
  missing photos and audit failure do not replace the current publication.
- An edit creates one published revision with the real actor and time. Replaced
  photos remain referenced by old revisions; newly uploaded files are cleaned up
  when a write fails. Publication metadata supplied in form data is ignored.
- History and withdrawal/archive controls are reachable from the editor. Existing
  internal draft-creation services and routes remain compatible; the Create
  observance button and reference-creation UI are removed from the Events page.
