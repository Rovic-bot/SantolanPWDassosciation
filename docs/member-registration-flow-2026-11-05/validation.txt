Onsite reference lookup, profile photo and editing — November 5, 2026

Requested behavior
- An approved application's AMR reference opens the member's standalone page.
- Remove Save as draft from onsite registration.
- Use the uploaded 2x2 membership picture as the profile photo, otherwise initials.
- Profile editing uses the onsite registration fields.

Implementation
The existing staff-only lookup now redirects approved applications directly to
members:detail when the actor has members.view_member. Original AMR references,
short aliases and reference digits remain supported. Pending/rejected records
retain their registration review pages. No extra lookup by name or PWD ID was added.

Removed both draft buttons, their temporary state and restore handlers. The
normal review dialog, file checks, explicit save and no-JavaScript submit remain.
The script version changed so already-open browsers receive the updated asset.

Member portraits now also resolve the active photo_2x2 RegistrationAttachment
retained by the approved intake's current revision. No photo is copied, moved,
published, or backfilled. Existing 2x2 supporting documents take priority, and
historical 1x1 portraits remain a fallback. Missing photos use existing initials.
The original private attachment endpoint supports inline preview only for 2x2
JPEG/PNG photos. Its existing authentication, document permissions, no-store
headers, attachment ownership and audit-before-delivery behavior are preserved.
Photo URLs are omitted when the staff member lacks source-document access.

The existing MemberRegistrationForm already uses AssociationPDFForm and the
shared onsite section/field templates. Verified field names, groups, choices,
required fields, prefilling and saving, including family and assessment details.
The required update reason, version checks and original registration history
remain separate from the current member profile.
