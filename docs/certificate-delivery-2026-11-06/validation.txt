Implemented behavior
- Recorded publication and private certificate jobs commit atomically. Only applications in the exact published selected-member rows receive a job. No eligibility, scores, selections, releases, or public result fields are changed by delivery.
- One immutable certificate per program application prevents duplicate certificates on repeated publication. Each contains the member's saved full name, published program name and local publication date. The original DOCX remains unchanged; its copy is packaged with the application.
- The application-provided email takes precedence; otherwise the onsite member email is used. Missing/invalid addresses remain pending with a correction message. A never-attempted job can pick up a corrected address through Retry pending certificates. Submitted payloads remain fixed for idempotent retry.
- One publication queues the selected members together. Background delivery sends separate recipient-only requests with DOCX attachments. The Resend batch API does not support attachments. Requests are paced at 0.6 seconds; 429 failures are retained for retry.
- Private status/downloads require current publication permissions. Certificate bytes and attempt history are retained in the database, not public media. Public result payloads contain no email addresses or certificate URLs.
- Resend acceptance is labeled as acceptance, not confirmed inbox delivery. Failures have sanitized explanations. Retries use the same provider idempotency key and payload; uncertain requests cannot automatically retry after 23 hours because Resend's protection expires at 24 hours. Check the Resend dashboard before any manual resend in that case.
- A queued job survives restart. A management command can drain queued jobs; blocked/failed jobs are retried explicitly in the preview after setup/correction. Already accepted certificates are never automatically resent. A selection must still be part of current published results before an attempt.
- Announcement and delivery history do not backfill past publications. An authorized administrator must explicitly publish results to create the first jobs for previously published programs.
